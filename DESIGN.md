## Brand
- Personality: playful architectural studio, handcrafted digital diorama, personal and discoverable
- Trust signals: visible résumé-to-exhibit mapping, familiar room names, immediate demo generation
- Avoid: monochrome gallery minimalism, unnecessary room proliferation, generic SaaS dashboard chrome, an empty public showroom, importing a complete third-party room scene

## Product goals
- Goals: explain the résumé-to-space mechanism before intake; perfect one résumé-to-home demo; make the Agent wait useful through pet and photo setup; make spatial discovery happen through the home itself; couple every navigation step to a camera transition; make loading progress trustworthy; add locally persistent physical-stand heat, a personalized roaming companion, profile-grounded QA, and a three-track open-license music box
- Non-goals: multiple demo personas, photorealism, publishing workflows
- Success signals: a visitor enters only after the scene is truly ready, feels positioned at human eye height, can open an exhibit as a face-forward full reading surface, jump to a stand from the heat list, ask the companion about public profile facts, and control unobtrusive music

## Personas and jobs
- Primary personas: creative developers, designers, artists, and professionals who want a distinctive portfolio
- User jobs: preview the concept quickly; submit a résumé; understand how personal information becomes architecture
- Key contexts of use: desktop exploration; this MVP's visual acceptance is desktop-only

## Information architecture
- Primary navigation: one quiet start-creation action over the process artwork plus a return-to-process action on intake; website and résumé are independently selectable, may be combined, and commit through one bottom generate action; saved recent profiles and one permanent featured demo remain separate shortcuts; generated world uses the front door, stairs, a single return-home control, back controls, and exhibit selection
- Core routes/screens: interactive process landing, intake screen, Agent parsing/move-in desk, loading cover, and generated-home screen
- Content hierarchy: single-screen process artwork → intake, saved profile, or permanent demo → Agent wait with pet customization → move-in photo placement → 100% scene-loading cover → home exterior → public showroom → front résumé wall / project islands / visitor corner → open second-floor gallery → profile-scoped photo frames and password-gated diary book
- Content-to-object mapping: identity and biography → portrait frame; work and education → chronological timeline; skills and tools → compact capability matrix; achievements and measurable impact → highlight plaque; contact links → contact card; projects → paired side-wall posters and rotating low-plinth image cards; move-in photos → six customizable second-floor frames; visitor messages → corner board; in-world private text and optional images → bedroom diary

## Design principles
- Reference-first introduction: rebuild the supplied editable PPT artwork as independently positioned web elements rather than using a flattened slide background. Keep the original ROOM mark, pixel people, document illustrations, Agent pictograms, generated house, and color relationships, but organize them into one restrained editorial input → Agent pipeline → world composition. The three stages share one optical center and one scale system; source material stays compact, Agent cards behave like a process diagram rather than dashboard panels, and the house remains the visual destination without dominating the viewport. Avoid added navigation bars, side rails, generic cards, or scrolling. Motion belongs to the extracted visual elements and their connectors.
- Editorial headline: the landing headline is “把你的经历，变成你的世界。” It is the only large text on the page, centered against the ROOM mark with no competing top-level labels or decorative chrome.
- Optical asset scale: landing illustrations are normalized by their visible alpha bounds rather than raw PNG canvas dimensions. The PDF and WEB profile are peer input documents and must occupy the exact same visible width and height on one vertical axis; their CSS boxes compensate for each PNG's different transparent padding. The WEB profile remains the focal sheet through position and motion only, the owner is roughly four-fifths of its visible height, Agent pictograms are normalized to one optical icon box, and the visitor remains intentionally smaller than the generated house.
- Shared stage frame: INPUT, PROCESS, and WORLD use one heading baseline, one body height, and one connector axis. The PDF and owner converge around the WEB profile sheet before the flow enters the Agent stack; independent vertical centering per column is forbidden because it breaks the single-diagram reading.
- Anchored creation action: “开始创建” is the sole primary action and remains in the viewport's lower-right corner, independent of the three-stage diagram.
- Directional handoff: the landing exits toward the left and intake enters from the right; intake exposes a visible “查看流程” control that reverses the transition without a route reload.
- Continuous page family: landing and intake share the ROOM image mark, blue-gray ink/rules, compact mono labels, editorial Chinese typography, restrained radial paper background, and dark-blue primary actions. Intake must feel like the next working state of the landing—not a separate black-and-white campaign page—so heavy black frames, oversized repeated headlines, and unrelated button geometry are forbidden.
- Deliberate source commit: entering a website or selecting/dropping a résumé only updates a visible source draft. Neither action starts parsing. Website and résumé are optional individually but at least one is required; one bottom “生成我的 ROOM” action summarizes the selected sources and starts the pipeline. When both are provided, the Agent parses them as complementary sources and merges the resulting profile.
- Useful intake depth: the second page uses a larger editorial headline and a compact animated source-to-space preview below it. The preview explains five concrete outputs—project stands, experience route, food display, hobby collection, and Xiaobai knowledge—while reflecting whether WEB and CV sources are ready; motion is limited to route/scan feedback and respects reduced motion.
- Honest scene reveal: working progress is capped at 99%. The 3D canvas remains fully covered until tracked resources settle, the portrait settles, the Suspense scene commits, WebGL compilation finishes or takes a controlled degraded path, and stable frames render. The UI switches to 100%, stops the spinner, and reveals the scene in the same completion transition; it must never show “100%” while still visibly busy.
- Exhibit comes to the visitor: selecting a public résumé surface pauses free movement, completes the authored camera approach, then opens a centered face-forward reading screen. The old right-side paper detail is not used for public exhibits; utility tools remain independent panels.
- Grouped exhibit reading: when one stand contains several projects, experiences, education entries, or achievements—or one grouped entry becomes long—the immersive reading screen separates each semantic item into a soft warm-white card. Cards use restrained teal rules, compact metadata, and generous line height; they clarify item boundaries without becoming dashboard tiles or truncating the complete display copy.
- Honest demo heat: the heat sidebar is explicitly labeled as seeded demo values plus this browser's accumulated views. One row equals one physically rendered, camera-focusable public stand: a semantic information stand or a visible project pedestal. The ledger never expands to every parsed source item, never includes diary/private-frame content, and every item resolves to a real camera target before it can be activated.
- Profile-scoped ROOM companion: every home contains the same lightweight procedural companion skeleton, but the owner chooses its validated short name, body/accent palette, ear shape, face marking, and personality during the Agent wait. The choices are stored by profile ID and reapplied whenever that profile is reopened; source pet names and imagery are still ignored. The chosen name appears consistently in the move-in preview, world controls, pet-bed nameplate, QA surface, and QA identity prompt.
- Profile-grounded companion answers: QA receives only the parsed public profile, cites the items supporting an answer, and says when the profile does not contain the requested fact. A validated companion name and personality enum contribute only the fixed identity/tone instructions to the system prompt; arbitrary client prompt text is never accepted. QA never reads diary, guestbook, private frames, or executes instructions embedded in source text.
- Consensual ambient sound: background music can start only from the visitor's explicit enter gesture, stays at low volume, has a persistent HUD toggle, pauses while the page is hidden, and never participates in the critical scene-loading gate. The in-world gramophone ships with three locally bundled open-license instrumental tracks, exposes a compact track picker, and still accepts a session-only local audio override.
- Floor-aware stair invitation: a translucent in-world sign floats above the real stair path. On the ground floor it says “点击上楼”; on the upper floor it says “点击下楼”. The sign and stair treads share one click target and trigger the existing authored camera route in either direction.
- Display-first Agent copy: evidence, locators, line numbers, and parsing jargon remain in structured profile data for audit and QA but never appear in public exhibit copy. Display titles, summaries, tags, and metadata are normalized into concise, human-readable information highlights before world orchestration; source access is offered as a link, not raw evidence labels.
- Progressive provider setup: the second-page settings dialog asks for one primary API key first. Image generation and companion QA reuse that provider by default; independent website, image, and QA providers live behind clearly labeled advanced overrides. Repeated provider fields stay hidden until their override is enabled, while saved legacy configurations remain compatible.
- One small house, two roles: the first shot must read as a small villa facade; the public showroom holds all résumé content while the password-gated private bedroom holds a local personal diary
- Spatial navigation first: never begin with a dollhouse overview or room tabs; the door, room thresholds, and exhibits are the primary navigation targets
- Camera follows intent: entering the villa, entering a room, and selecting an exhibit each produces a progressively closer camera composition
- First-person exploration: after the authored entrance route, desktop visitors use WASD to walk, drag the pointer for full 360° horizontal look with bounded pitch, and press Q or E for a smooth 180° left/right turn. Radius-aware mesh collision and floor bounds prevent walking through walls or outside the home. Click-driven room and exhibit camera routes always take priority.
- Oblique display, frontal reading: showroom objects may sit at side-facing angles; selecting one moves the camera along that object's own facing vector until its content is readable head-on
- Human-scale occlusion: exterior, public showroom, and the second-floor gallery coexist in one coordinate system; architecture controls sightlines without using a password to block spatial exploration
- Fixed viewpoints: each stage has an authored eye-level camera position and target; the exterior camera sits below the facade midpoint and looks slightly upward
- Full-frame embodiment: the canvas is the visitor's field of view, never a black presentation stage around a room model; interior frames must be filled by floor, walls, ceiling, doors, furniture, and light
- Threshold orientation: after crossing a side door, the camera stands just inside that exact doorway and faces into the room from that side, preserving the direction of travel
- Human room scale: interior rooms are substantially larger than their exhibit clusters; the eye sits at 1.66 m and begins one human step inside the threshold, never outside the room shell
- Expanded floor plan: the public showroom and private bedroom use twice the previous width and depth while retaining human-height ceilings and objects. The villa threshold remains fixed, so the extra depth extends inward rather than separating the facade from the entrance.
- Continuous thresholds: door rotation and camera travel begin together; the camera follows authored approach, threshold, and arrival waypoints without teleporting, unmounting the destination, or exposing an empty gap
- Entry clearance: exhibit layouts leave a walkable buffer between the threshold and the first interactive object so nothing appears pressed against the visitor's face on entry
- Object-level reference boundary: open-source projects supply individually named display-support nodes such as a catalog table, screen, lamp, shelf, books, contact letter, radio, skill object, globe, bench, and lantern. Decorative furniture without an information role is excluded; complete rooms, terrain, vehicles, and original layouts are never inserted.
- Information before decoration: every retained object must help present, index, illuminate, archive, or navigate résumé content. Empty visual filler is removed even when a suitable model is available.
- Layered exhibit copy: Agent extraction and source evidence remain complete in the saved profile, while physical project and publication text surfaces receive a deterministic editorial projection: content type, concise title, venue/status/time, and one short takeaway. Source illustrations remain unchanged. Clicking the frame reveals the complete text, link, and evidence, and the owner can edit those full fields locally; the compact text projection updates from the edit. This rule applies to material exhibits, not the personal introduction.
- Dense but legible: the public showroom uses three authored low circular project islands per page. One project occupies island 4; two occupy islands 4 and 5; three occupy islands 3, 4, and 5. Unused islands stay hidden, and the visitor corner and archive preserve the main walking route.
- Paired project representation: each project has one rotating flat image card on a low central plinth and one readable side-wall poster. Either object opens the same résumé-backed project detail, but each owns an authored camera focus that matches its physical orientation. Parsed website or résumé images should populate the card first; this demo renders a project-cover image fallback from the parsed title and summary.
- Résumé becomes architecture: the full résumé remains parsed and traceable inside the public showroom; every authored information surface is clickable and has a fixed close-view camera composition
- Abstract portrait only: a source photo is an identity input, never a public exhibit. Creating a world automatically sends that photo to the configured image service, and the 3D portrait remains behind the loading cover until generation settles. The generated image never overwrites the saved source URL or its evidence; a non-photographic placeholder is used if generation fails, with a retry action in the profile detail.
- Playful deconstructed face: generated portraits use black ink-like strokes on warm white, broken contours, loops, sharp angles, asymmetrical negative space, and intentionally non-anatomical facial cues. They must never become a realistic, painted, or merely stylized version of the source photograph.
- Local personal memory: the second-floor diary is not another résumé category. Its text and optional images stay in browser local storage and require an owner or visitor credential before reading; the surrounding second-floor space remains open.
- Productive parsing wait: as soon as a URL or document enters the Agent pipeline, intake becomes a two-step move-in studio. The user first names and customizes the companion and chooses one fixed personality, then assigns up to six local photos to the existing second-floor frames. No diary text or diary image is created during onboarding; diary authoring begins only by interacting with the in-world diary.
- Profile-scoped local move-in data: pet name, appearance, personality, and optimized frame photos are saved under the parsed profile ID. Reopening a recent profile restores only that profile's companion and frames; data from one profile must never leak into another.
- Persistent generated people: every successfully parsed profile is stored locally, deduplicated by profile ID, and surfaced newest-first in the intake Demo / 最近生成 area. A saved card recompiles and opens the same profile without running Agent parsing again; the permanent Han Chen demo remains available.
- Private-room first view: the bedroom door is taller than the public-room display furniture and carries no floating placard. After crossing its threshold, the diary desk sits on the doorway's center axis, faces the arriving visitor head-on, and the open book tilts slightly upward for immediate recognition.
- Parsed project imagery: a source project's own thumbnail or embedded image is the preferred rotating exhibit. Before a source provides one, the demo renders the same parsed project content into a flat cover image; it must never fall back to an abstract 3D sculpture.
- Password boundary: the MVP uses transparent local demo passwords only when the diary book is opened. Owner mode can read and write; visitor mode can only read. The second-floor gallery itself never requires authentication.
- Tradeoffs: authored cinematic routes handle entry, stairs, and exhibit focus; free first-person movement resumes after each route. Both floors remain mounted for uninterrupted transitions.

## Visual language
- Color: warm terracotta and walnut architecture, cream plaster, moss and teal rooms, violet and amber emissive accents; exterior gaps use sky and landscape color, interior gaps use the current room envelope—never black stage color
- Material system: reuse the local lime-plaster, walnut-herringbone, terracotta-roof, and woven-rug texture sets from the isolated materials branch. They belong to architecture and display furniture only; parsed résumé/project images remain the content layer.
- Typography: editorial oversized Chinese headline, compact mono labels, readable sans-serif supporting text
- Spacing/layout rhythm: the landing uses one compact horizontal narrative centered vertically inside a single viewport, with generous outer margins, narrow connector columns, consistent stage headings, and deliberately unequal content weights that build toward the house. Intake inherits the same outer margins and header rhythm, then resolves into a quiet two-column source-selection workspace with an internal scrolling recent-profile list; the 3D field of view remains full viewport and controls stay compact and floating.
- Shape/radius/elevation: architectural hard edges with selectively rounded UI cards; layered podium, facade, roof beams, furniture, and lighting
- Motion: a quiet page handoff plus source convergence around the WEB sheet, a traveling connector pulse, sequential Agent scan, visitor movement, and staggered room-light animation inside the generated house; motion must reveal transformation order rather than make every asset float independently. The home then uses one continuous centripetal, arc-length camera curve across entrance corners and authored spline routes elsewhere. Door motion and camera travel stay synchronized; idle desktop views smoothly follow the pointer while focused views use a reduced range.
- Imagery/iconography: the landing uses the transparent source artwork extracted from the editable PPTX, with HTML/CSS owning labels, connectors, and layout. ROOM authors data-driven portrait, timeline, tool matrix, plaques, thematic project posters, walls, doors, cameras, and layout; individually extracted open-source screens and archive objects support the content without competing with it. AI portrait art uses pure black expressive strokes on warm white with no gray, color, shading, realistic texture, or filled facial planes.

## Accessibility
- Target standard: keyboard-operable form, tabs, buttons, and room navigation; readable HTML detail for selected exhibits
- Keyboard/focus behavior: the blueprint handoff, featured demo, move-in steps and choices, photo upload/removal, contextual navigation, heat entries, music toggle, companion QA, and portrait retry action use native controls; immersive exhibit and QA dialogs accept Escape and restore focus; the diary has a keyboard-accessible password form with focused input, cancel, and submit actions; guestbook and diary editors use labeled native form controls
- Contrast/readability: dark text on warm light UI; translucent world overlays retain opaque backing
- Screen-reader semantics: tablist/tab/tabpanel relationships and named world region
- Reduced motion and sensory considerations: CSS reduced-motion support; camera motion remains gradual and non-flashing

## Responsive behavior
- Supported visual-acceptance device: desktop 1280×720 and wider
- Layout adaptations: the landing preserves the same three-stage horizontal story down to the in-app browser's narrow desktop panel by using fluid columns, smaller typography, reduced document/Agent scale, and a simplified visitor comment—never horizontal overflow or a second page. The intake screen may still collapse through existing CSS; the 3D showroom keeps one authored spatial composition while immersive exhibit and QA screens become full-viewport sheets and the heat sidebar collapses after navigation on narrow screens.
- Pointer behavior: every exhibit responds to click; hover is enhancement only

## Interaction states
- Loading: URL/file parsing moves into a dedicated progress workspace with a lightweight pet customizer and local frame-photo picker; after parsing is ready and profile-scoped move-in data is saved, the user explicitly enters the home. An opaque full-viewport architectural loading screen keeps the 3D canvas hidden while local material maps, environment images, GLTF/DRACO objects, parsed project images, the abstract portrait, scene commit, shader compilation, and stable frames settle. Progress is monotonic and capped at 99 until every reveal gate is satisfied; 100 is rendered only with a stopped completion indicator and immediate reveal.
- Empty: intake screen includes one immediately usable featured résumé; its generate action remains disabled until a website or résumé is selected
- Error: concise form message near the input; portrait generation failures retain the abstract placeholder and offer retry without exposing the source photo
- Success: the stable generated home appears only after the complete readiness gate; its parsed profile is listed in Demo / 最近生成 after refresh and can be reopened without parsing; its customized companion name, appearance, fixed QA tone, and six frame assignments reappear with that profile only; project and publication frames remain glanceable while retaining full editable detail without surfacing raw evidence syntax; a successful portrait generation updates the 3D portrait and exposes an AI-art label; the translucent stair sign changes direction by floor and enters the destination floor immediately; the music box switches among three bundled tracks; clicking the diary opens authentication, and valid owner/visitor credentials reveal the corresponding editable/read-only view; saved guestbook and diary entries reappear after refresh in the same browser
- Disabled: generation buttons communicate disabled state through opacity
- Offline/slow network: local demo résumés remain available without network access

## Content voice
- Tone: direct, imaginative, architectural
- Terminology: house for the complete result; room for a semantic section; exhibit for an individual résumé item
- Microcopy rules: describe the transformation concretely; lead with personal information and outcomes; never render raw `line`, `page`, `locator`, or `evidence` markers in the visitor-facing experience; avoid agent/RAG/security jargon in the primary experience

## Implementation constraints
- Framework/styling system: Next/vinext, React Three Fiber, Three.js, repository-native CSS
- Design-token constraints: extend existing CSS variables rather than add a second design system
- Performance constraints: begin preloading the shared home GLB and constant exhibit assets when the user advances to intake; retain both authored floors in one canvas; keep the procedural companion mesh budget effectively constant across customization variants; keep the scene's light-node count stable across floors; precompile the complete WebGL scene before ending the loading cover; use one continuous arc-length entrance curve and cap route delta so a slow frame cannot jump at a corner; hold the visible progress below 100% until resources, portrait generation, shader compilation, and the committed scene are all ready; cap saved profiles at six, canvas DPR at a quality/performance ceiling of 1.2, the main shadow map at 1024, diary images at 1 MB, move-in frame images at 960 px / compressed JPEG, and source portraits at 8 MB; delay media-texture disposal briefly to avoid rapid dispose/reload churn during adjacent exhibit navigation
- Privacy constraints: source portraits are fetched through the existing validated media proxy only for automatic abstract transformation; image-service credentials remain server-side, and source/generated image bytes are neither logged nor persisted by the server. Intake copy discloses the transformation before submission.
- Compatibility constraints: preserve Cloudflare-compatible build; local-only delivery for this iteration
- Test/screenshot expectations: landing-source regression, profile-scoped move-in persistence regression, pet personality prompt regression, in-world diary regression, upstairs-preload regression, scene-entry gate regression, pipeline tests, lint, build, rendered HTML smoke test, and desktop move-in/world interaction QA.

# Mardou 展馆取点与交互迭代记录

更新日期：2026-07-31

## 1. 自动取点与布局规划

- 已解析 `MardouMuseumResult.glb` 的楼层、墙体、图片网格与主要动线。
- 已产出 17 个真实规划点：一楼 14 个、二楼 3 个，其中 8 个为贴墙或近墙点。
- 点位、楼层、区域、建议内容、摆放方式、墙面法线、模型图片映射、交互审计与测试用例统一记录在：
  `outputs/mardou-layout-planning/mardou-point-layout-plan.xlsx`。
- 33 个既有布置点通过地面支撑与至少 1.2 单位结构净空审计；5 条相机路径通过逐段采样审计。

## 2. 楼梯与穿墙修复

- 楼梯交互按 GLB 的真实水平三角面重建为 13 级下段踏步、1 个平台和 7 级上段踏步，共 21 个贴合表面的浅层点击体。
- 删除通过宽泛坐标范围判断楼梯的逻辑，楼梯周边与下方空间不再被整体误判。
- 第一人称移动改为相机半径感知的 3 高度 × 3 横向射线探测。
- 对角移动受阻时按 X/Z 轴分别尝试，保持沿墙滑动，不会因为一个方向受阻而完全卡死。
- 自动门继续使用独立碰撞状态：关闭时阻挡，开启时允许通过。

## 3. 独立取点器与 skill

- `tools/mardou-museum-picker` 已升级为 Pointer Lock 第一人称取点器：WASD、360° 水平环视、受限垂直环视、中心准星取点、JSON 导出。
- 取点射线只使用最近命中；表面法线转换为世界坐标后再保存。
- 外包围盒限制与真实网格碰撞同时生效，分别负责防止离开模型和穿过内部墙体。
- 已同步更新 Codex skill 与用户提供的 skill：
  - `~/.codex/skills/glb-coordinate-picker/SKILL.md`
  - 用户提供的 Claude skill 目录中的 `glb-coordinate-picker/SKILL.md`
- 两份 skill 均通过 `quick_validate.py`，内嵌 `picker.js` 模板通过 Node 语法检查。

## 4. 图片网格优化

- `Picture_1` 保留在 GLB 场景数据中，但默认隐藏且不参与拾取。
- `Picture` 与 `Picture_2` 可分别通过图片 URL 或本地文件替换贴图，也可独立恢复 GLB 默认贴图。
- 自定义值保存在浏览器本地存储；远程图片通过受保护的 `/api/media` 入口加载。
- 替换贴图在回收时会释放 GPU 资源，避免多次编辑累积纹理内存。

## 5. 验证结果

- `npm test`：137/137 通过。
- Mardou 布局审计：33 个点位、5 条相机路径全部通过。
- 生产构建与 SSR 测试通过。
- `npm run lint` 通过。
- `git diff --check` 通过。
- 浏览器实测：展馆进入、图片位配置、独立 URL 替换与保存状态正常；无应用错误日志。
- 独立取点器页面、GLB 和界面加载正常且无初始日志错误。自动化 Chromium 会拒绝 Pointer Lock，因此最终的真实鼠标锁定、WASD 撞墙和角落滑动仍应在普通浏览器中由一次真实点击手势复核。

## 6. 已知非阻断项

- 构建仍有既有的单个大于 500 kB chunk 警告，不影响本轮功能与测试。
- Three.js 输出既有 `THREE.Clock` 弃用警告，不影响运行；可在后续性能整理时迁移到 `THREE.Timer`。
